Oxfmt divergences (all 3 seen; fewer than the 10 asked for exist): 2× TS union type alias `type X =\n  'a' | 'b' …` → leading-pipe one-per-line (`packages/db/src/billing.ts`, `packages/db/src/schema/billing.ts`); 1× CSS `font-family:` list that Prettier breaks one-per-line, joined onto one line (`apps/site/src/styles/site.css`). Class: divergence, not config gap (no option maps to either); not established as a bug. Both outputs are stable under their own tool.

## Blockers (Oxlint)

1. **`eslint-plugin-oxlint`'s generated off-list switches off boundary rules** (44/112 fixtures fail). Usable only with `no-restricted-imports` and `typescript/no-require-imports` hand-removed from the Oxlint config, and that exclusion must be kept forever (a re-run of `@oxlint/migrate` brings them back).
2. **Oxlint's `no-restricted-imports` silently ignores patterns it can't handle.** The module-boundary pattern (`billing/(?!(entitlements|policy)…)`) and the normalized-path pattern never fire, with no config error or warning: `../billing/service`, `../organizations/service`, `../server/./db` all pass. Moving import boundaries to Oxlint would drop invariant 3 without a signal.
3. `no-restricted-syntax` isn't implemented natively (the 14 SQL, dynamic-import and module-boundary selectors stay in ESLint).
4. No measurable full-pipeline gain: P2 − P1 = 0.2 s, inside run-to-run spread (P1 range 1.6 s). Lint-only gain 0.6 s.

No Oxfmt blocker found.

## Assumptions (docs or inferred, not measured)

- The silent misses in blocker 2 are from lookahead `(?!…)` (Rust `regex` has no look-around). Inferred: every missed pattern contains one; `../organizations/service` misses because it's in the same regex as the lookahead alternative.
- Oxfmt "is compatible with Prettier v3.9.9 for many configurations" and documents intentional divergences (ctx7 `/websites/oxc_rs`, migrate-from-prettier page); I didn't find these two specific cases listed.
- Oxlint JS plugins are alpha / not semver and lack type-aware rules (prompt facts from Oxc docs; not re-checked).
- Oxfmt is 0.x; pinning it exactly (like Astro/Starlight) is assumed necessary.
- `apps/app/scripts/export-plans.ts` formats `plans.json` with Prettier's Node API (`format`, `resolveConfig`); whether Oxfmt has a comparable API wasn't checked during the spike (resolved in the Oxfmt adoption PR; see ADR-0006).
- Cold CI timings (fresh runner, no page cache) weren't measured; the relative gap is assumed to hold.

## What adoption would need (Oxfmt only)

- **ADR-0006 note** (it names "ESLint + Prettier"; a formatter swap with ESLint unchanged fits a dated note, like its ESLint 10 note). No new ADR unless the owner wants one.
- **One PR** (`build(tooling): format with Oxfmt instead of Prettier`): `.oxfmtrc.json` from `--migrate=prettier`; `format`/`format:check` scripts; reformat the 3 files; drop `prettier`, `prettier-plugin-astro`, `.prettierrc.json`, `.prettierignore` (patterns move into `ignorePatterns`; release-please's CHANGELOG ignore must survive, ADR-0029); resolve `export-plans.ts`'s Prettier API use (Oxfmt API or a CLI call; `pnpm plans:check` must stay green); keep `eslint-config-prettier` (it only switches off ESLint style rules) or swap to an equivalent; `.github/dependabot.yml` (drop `prettier-plugin-astro` from the Astro group, pin/group `oxfmt`); AGENTS.md commands/toolchain lines; docs/site `astro check` unaffected.
- Expected effect: about −5 s of ~32 s `pnpm check` (−15 %) locally; typecheck (~15 s) stays the dominant cost.
- Timing: the spike proposed after M1; on 2026-10-21 the owner decided to adopt Oxfmt now and to defer Oxlint ([README](README.md)).
