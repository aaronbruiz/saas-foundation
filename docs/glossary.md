# Glossary

Foundation terms and the distinctions that matter when changing the code. Each entry links the file or ADR that defines it; those stay the definition of record, and the PR that introduces or renames a term updates its entry here. A product's own terms go in `docs/product/glossary.md` ([ADR-0041](adr/0041-product-owned-documentation-and-agent-instructions.md)).

## Tenancy and access

| Term                      | Meaning                                                                                                                                                                                                                                                                               | Defined in                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Tenant, organization      | The same thing: a Better Auth organization is the tenant. Tenant-owned rows carry `organization_id`.                                                                                                                                                                                  | [ADR-0005](adr/0005-better-auth-identity-app-owned-authorization.md), [ADR-0010](adr/0010-path-based-tenancy.md) |
| Membership                | A user's `member` row in an organization, with its role. Every tenant request is checked against it.                                                                                                                                                                                  | [`server/context.ts`](../apps/app/src/server/context.ts)                                                         |
| Tenant context (`ctx`)    | What `getTenantContext(db, headers, slug)` returns after checking session → slug → organization → membership: the user, the organization (`ctx.orgId`, slug, name) and the member's role. Repositories take it; no session is 401; an unknown or invalid slug or a non-member is 404. | [`server/context.ts`](../apps/app/src/server/context.ts), AGENTS.md invariant 1                                  |
| Slug vs organization id   | The slug (`/t/<slug>`, or the `tenant` input of a server function) is a **selector**: it names the tenant asked for. The organization id from the tenant context is the **authority**. `organizationId` is never an input, and `activeOrganizationId` only picks the landing page.    | AGENTS.md invariants 1 and 9, [`packages/contracts`](../packages/contracts/src/index.ts) (`TenantSlug`)          |
| Role → capability         | Roles (`owner`, `admin`, `member`) map to capabilities (`project:create`, `billing:manage`, …) in one matrix; code asks `authorize(ctx, capability)`, never the role.                                                                                                                 | [`server/permissions.ts`](../apps/app/src/server/permissions.ts)                                                 |
| 404 vs 403                | **404** for an unknown tenant, a non-member or another tenant's resource: nothing leaks whether it exists. **403** only for a member of the tenant whose role lacks the capability.                                                                                                   | AGENTS.md invariant 5                                                                                            |
| Owner (role) vs the owner | `owner` is an organization role (the member who alone deletes the organization and manages paid billing). In the repository's docs, "the owner" is the repository operator who approves merges, releases and spending.                                                                | [`server/permissions.ts`](../apps/app/src/server/permissions.ts), [roadmap](roadmap.md)                          |

## Billing

| Term                                     | Meaning                                                                                                                                                                                                                                                                   | Defined in                                                                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Plan → entitlement → subscription status | A **plan** (in `policy.ts`) grants **entitlements** (limits and features). The provider's **subscription status** decides which plan applies, through the policy. Authorization reads entitlements only (`entitlementsIn(db, ctx.orgId)`), never a status or a plan name. | [`billing/policy.ts`](../apps/app/src/modules/billing/policy.ts), [ADR-0020](adr/0020-billing-product-policy.md), AGENTS.md invariant 6 |
| Provider                                 | The billing service behind an adapter: Polar, as merchant of record. Only `modules/billing/providers/**` knows it.                                                                                                                                                        | [ADR-0022](adr/0022-polar-merchant-of-record.md)                                                                                        |

## Data access

| Term                        | Meaning                                                                                                                                                                                                                                                                                     | Defined in                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Repository                  | A function in `packages/db` that queries for a tenant given `ctx.orgId`. The only way app code reaches tenant data; a `Db` is an opaque handle only repositories can use.                                                                                                                   | AGENTS.md invariant 2, [`packages/db/src/tenancy.ts`](../packages/db/src/tenancy.ts)                                              |
| `inTenant` / `enterTenant`  | `inTenant(db, ctx, fn)` runs `fn` in its own transaction with the tenant (`app.org_id`) set transaction-locally; every tenant-table statement goes through it. `enterTenant` sets the tenant once inside an already running transaction (the billing webhook, after its organization lock). | [`tenant-transaction.ts`](../packages/db/src/tenant-transaction.ts), [ADR-0040](adr/0040-tenant-row-level-security.md) decision 1 |
| `GuardedClient`             | The only pg client `createDb` makes. Defense in depth, not the boundary: it refuses a statement on a connection a tenant transaction owns unless it runs inside that transaction, and refuses statements that set the tenant context outside `inTenant`/`enterTenant`.                      | [`connection.ts`](../packages/db/src/connection.ts), [ADR-0040](adr/0040-tenant-row-level-security.md)                            |
| `app_owner` / `app_runtime` | `app_owner` owns the schema and runs migrations, backups and previews. `app_runtime` is the least-privilege role the app connects as, with explicit per-table grants.                                                                                                                       | [ADR-0038](adr/0038-least-privilege-database-runtime-role.md), AGENTS.md invariant 7                                              |
| Archive                     | The owner-owned `archive` schema: deleted tenant rows and access-granting auth writes, captured by triggers, out of the runtime role's reach.                                                                                                                                               | [ADR-0039](adr/0039-archive-and-audit-triggers.md)                                                                                |

## Delivery

| Term                                        | Meaning                                                                                                                                                                                        | Defined in                                                                                                        |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Preview                                     | A per-PR deployment on workers.dev with its own Neon branch and Hyperdrive config, never production data.                                                                                      | [ADR-0021](adr/0021-per-pr-preview-data-behind-a-trusted-boundary.md), AGENTS.md invariant 15                     |
| Release candidate                           | A new app version uploaded and deployed at 0% of traffic, smoke-tested through a version override, then promoted to 100%.                                                                      | [ADR-0029](adr/0029-releases-deploys-and-rollback.md) decision 3                                                  |
| Release                                     | A version tagged by release-please from its release PR and promoted to production.                                                                                                             | [ADR-0029](adr/0029-releases-deploys-and-rollback.md), [runbook "Releases"](runbooks/README.md#releases-adr-0029) |
| Merged / validated / deployed / operational | Four different states of a change, reported separately: on `main`; hosted CI passed on that commit with the platform exercised; serving production; running unattended with working detection. | [roadmap "Status vocabulary"](roadmap.md#status-vocabulary)                                                       |

## Repository

| Term                 | Meaning                                                                                                                                                                                | Defined in                                                                                                                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Foundation / product | The **foundation** is this repository. A **product** is its own repository cloned from it, keeping the foundation as `upstream`; its own docs live in `docs/product/`.                 | [`start-new-product.md`](runbooks/start-new-product.md), [ADR-0027](adr/0027-polyglot-service-and-repository-boundaries.md), [ADR-0041](adr/0041-product-owned-documentation-and-agent-instructions.md) |
| Project              | The foundation's sample tenant-owned resource: the complete pattern (table, repository, server functions, pages, tests) a product copies for its first feature. Not a product concept. | [`start-new-product.md`](runbooks/start-new-product.md) step 6                                                                                                                                          |
